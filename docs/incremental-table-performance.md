# 增量报文视图与性能诊断

Trace 和分组模式共享已筛选记录缓存。正常刷新仅筛选新到帧；Trace 保留最近 1500 条匹配记录，分组保留环形历史范围内每个 key 的最新匹配帧。分组排序后最多显示 1500 条父报文，展开信号随父报文显示。

过滤器、显示模式、排序、展开状态、DBC 快照或时间格式变化，以及强制刷新，会重建缓存。历史淘汰时删除已失效的匹配记录；数据过滤保留最新“匹配”帧，而不是用不匹配的新帧覆盖它。

行块按帧序号及显示状态复用，包含展开 DBC 信号。未变化的行不重新格式化或解码，也不发送 set_row_data 通知。超时和新帧高亮仍纳入更新判断。Trace 滚动造成行位置变化时仍需更新对应行，排序和模型比较也不是零成本。

状态栏字段：

- UI：上一次 refresh_ui 的同步执行耗时 / 本次进程峰值，单位 ms；不包含 Slint 后续绘制和此前的事件接收处理。
- Q：最近一次后端健康报告的接收队列深度。
- D：接收队列报告的累计丢帧数。
- T：最近一次表格重建耗时 / 峰值，单位 ms。
- rows：最近一次表格更新通知的行数。
- RX、CMD、REC、HW、TS：既有队列、记录、硬件和时间戳诊断。长文本仍受状态栏可用宽度限制，优先显示 UI / Q / D。

模块边界：src/ui_refresh.rs 负责 UI 模型同步；src/can/send_queue.rs 负责有界发送队列和时间片；modbus/src/backend/grid.rs 负责寄存器与派生值行构建。三处大文件已开始按职责拆分，尚未全部拆完。

验证：

- 7 项表格测试通过，覆盖 10 万帧增量扫描、数据过滤、环形淘汰、Trace 与分组全量结果对照、暂停时强制刷新和信号顺序。
- 200 次刷新 / 10 万历史 / 每次 1 帧的 debug 索引微测试：全扫描 2913.890 ms，增量 0.604 ms。只衡量索引处理，不能当作整窗或真实总线性能。
- CAN 测试 26 项通过；3 项需要硬件或长期运行的测试未执行。
- Modbus 测试在工程根目录运行时 48 项通过。cargo test 默认切换到 modbus 子目录时，既有版本号测试因相对路径找不到 product-version.txt 而失败；本轮未修改该无关测试。
- 状态栏截图 artifacts/ui-review/performance-health.png 使用示例诊断数值，仅验证显示。

尚未进行物理总线满载、曲线与多组 DBC 展开同时运行的长时间测量，不能据此承诺运行中完全无卡顿。
