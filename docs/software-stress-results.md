# 无硬件压力测试（2026-09-05）

后续 UI 改动及默认 Trace 300 行复测见 [UI 修复记录](ui-improvements-20260905.md)。以下调度对比保留原 1500 行基线，避免混淆不同显示工作量。

## 已修复

- IPC 批量发送和文件发送不再在 UI 线程 recv_timeout 等待 500ms；最多保留 128 个待确认任务，定时器非阻塞取结果，保留 QUEUE_REJECTED / TIMEOUT 错误语义。超时状态未知，不自动重试。
- 批量接收帧整批提交记录队列，避免逐帧产生大量队列项。启用触发器时仍按逐帧逻辑处理，保留精确的触发边界。
- CAN 字节显示复用 256 个十六进制 SharedString，完整数据文本一次构造，减少 64 字节 Trace 行的分配。

## 调度分离复测

接收改为独立 10ms 定时器，每轮预算 4ms、最多 2000 个事件；UI 保持 100ms 刷新。两者仍在同一个 UI 线程，不是新增接收工作线程；预算在事件之间检查，单批处理可能超过 4ms。确认回执也在快速定时器中轮询。
